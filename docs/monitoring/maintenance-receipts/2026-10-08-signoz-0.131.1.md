## Refusals and Guardrails

Early attempts were retained and corrected at their owning boundaries:

- Compose omitted an unattached volume. Retained manifest state and actual runtime
  mounts now both participate in the inventory; a fixed preceding volume count
  cannot omit a new job's anonymous mount. The incomplete checkpoint was marked
  `complete=false`; restore refused it before creating volumes/containers.
- The private adapter escaped rendered shell commands twice. Source Compose's
  `$$` boundary is decoded before freezing runtime strings; production commands
  were not altered to accommodate the adapter. The failed init exited 2 before
  database migration, and its logs/config remain retained.
- ClickHouse's JSON integer quoting changed. Count/time-bound comparisons now use
  typed integer measurements, with identical values still required.
- Direct offline reads of a read-only WAL-mode SQLite directory failed. After
  quiescing writers, verification copies the complete file set into writable
  disposable scratch space, checks integrity, and reads there; the actual volume
  remains read-only. No WAL is dropped or changing state treated as immutable.
- A retry needed the held ClickHouse resumed for read-only retained-data queries.
  Current storage readiness is now checked before cold-probe artifacts are created.
  Only the copied storage was resumed; writers stayed stopped.

These findings are promoted into the prepared-release README. Restore regression
tests now cover an unattached manifested volume, refusal of an unmanifested runtime
anonymous volume, and preservation of actual runtime shell-dollar strings.
