## Source-Bound Reconciliation Contracts

An initial exact-row application comparison stopped on the built-in AI overview
dashboard, not user-owned data. A second comparison stopped on default mapping
settings. The app was left stopped and the collector was not advanced. Those
failed attempts remain failed under `stages/0.145.0/exact-preservation-attempt-1/`
and `stages/0.145.0/ai-exact-preservation-attempt-2/` in the candidate.

The root cause is an ownership mismatch in the rehearsal comparator: vendor-owned
versioned defaults legitimately reconcile on startup, while user-owned objects
must remain exact. The fix belongs in this migration comparison, not in the app,
database contents or a blanket exemption from preservation checks.

The two named, pinned-source contracts are:

- `vendor-owned-ai-overview-template-v2-to-v3`: the same system dashboard ID,
  name, owner, permissions, geometry and variables; exactly 17 query filters gain
  `gen_ai.request.model EXISTS AND`, and three query types become
  `builder_ai_query`. Only that dashboard's data/update timestamp and its matching
  system version row may change. Every user dashboard, account and saved view
  stays exact. See the [versioned dashboard definition](https://github.com/SigNoz/signoz/blob/v0.145.0/pkg/modules/dashboard/impldashboard/fs/definitions/ai-o11y-overview.json)
  and [startup reconciliation](https://github.com/SigNoz/signoz/blob/v0.145.0/pkg/modules/dashboard/impldashboard/v2_module.go).
- `vendor-owned-default-message-copy-to-move`: system agent group version 1 to 2
  and LLM group version 2 to 3, with exactly eight message sources changing from
  `copy` to `move`. The legacy source attribute is removed after populating its
  canonical message target. IDs, conditions, enablement, priorities and all other
  fields stay exact, apart from those groups' reconciliation timestamps. The
  tool group, custom group and pricing remain exact. See the pinned
  [agent](https://github.com/SigNoz/signoz/blob/v0.145.0/pkg/modules/spanmapper/implspanmapper/fs/definitions/gen_ai.agent.json)
  and [LLM](https://github.com/SigNoz/signoz/blob/v0.145.0/pkg/modules/spanmapper/implspanmapper/fs/definitions/gen_ai.llm.json)
  defaults.

Both predecessor and candidate definitions are frozen with SHA-256 checks. The
ordinary restart preserves the reconciled v0.145 state exactly; the cold restore
independently proved that preservation too. Actual OpAMP and fresh synthetic
message movement passed both before and after restoration. Source analysis and
unit tests alone did not substitute for the native API/data gates.

A third refused check used the API/metastore field `operation` at the collector
wire layer. The [pinned adapter](https://github.com/SigNoz/signoz/blob/v0.145.0/pkg/types/spantypes/spanmapperprocessor.go)
emits `action: move` instead. The comparator now verifies exactly those eight
wire actions and every other active field, without changing runtime settings.
`opamp-attempt-3-failure.json` and its actual configuration remain retained in the
candidate stage. All 51 focused rehearsal tests currently pass, including
API/collector field separation and required removal of moved source attributes.
